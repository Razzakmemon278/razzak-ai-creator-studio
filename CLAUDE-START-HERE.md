# Claude Start Here — Razzak AI Creator Studio

Repository: https://github.com/Razzakmemon278/razzak-ai-creator-studio

## Mission
Continue the existing Razzak AI Creator Studio project in this repository. The owner uses Android only and needs a mobile-friendly, free-first workflow for AI tools, short-video creation, and social content.

## Non-negotiable safety rules
- Inspect the repository and current branch before changing anything.
- NEVER delete, rename, or overwrite existing files unless the owner explicitly approves that exact change.
- Prefer adding new files or a separate branch. Keep changes small and reversible.
- Do not publish to any social account, change profile details, spend paid credits, add paid APIs, or require payment-card setup without explicit owner approval.
- Do not expose or commit secrets, tokens, passwords, API keys, or personal data.
- Be honest about what is actually completed and what remains unverified. Never claim a deployment or upload succeeded without checking its result.

## First tasks
1. Read README.md, README-CREATOR-STUDIO.md, index.html, app.js, styles.css, docs/free-first-mobile-toolkit.md, and docs/platform-upload-checklist.md.
2. Inspect the current GitHub branch, open pull requests, and latest Actions runs. Do not merge an existing PR automatically.
3. Run safe checks/tests available in the repository and report any broken links, JavaScript errors, accessibility/mobile layout issues, and workflow failures.
4. Make the smallest safe fixes on a new branch, without modifying or deleting existing content unnecessarily. Explain each change and its reason.
5. Ensure the GitHub Pages workflow can deploy the existing static site. Do not add paid services or secrets as a requirement.
6. Improve the Creator Studio dashboard only after inspecting the existing implementation. Add useful links for free/mobile-friendly AI image, video, audio, caption, and social publishing tools; mark free-tier limitations clearly.
7. Prepare a professional ~2-minute vertical cartoon-video production plan using short scenes, consistent characters, narration, subtitles, and a QA checklist. Do not claim the MP4 exists unless a real rendered file is available and verified.
8. Provide the owner with exact simple Android steps and links. Ask only when a permission, paid action, public posting, or irreversible change is necessary.

## Required final report
Summarize: files inspected; files added/changed; checks run and their real results; deployment URL/status if verified; unresolved blockers; next single action for the owner.
